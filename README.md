# WebVIO: markerless monocular SLAM in the mobile web browser

WebVIO tracks a phone's camera and maps the scene **inside a web page**, so augmented reality works without installing
an app and without markers. It is built on parts of [ORB-SLAM3](https://github.com/UZ-SLAMLab/ORB_SLAM3) and runs as
WebAssembly (threads and SIMD) in a Web Worker. It keeps ORB-SLAM3's complete back end: local bundle adjustment, loop
closing, multiple maps, relocalization, and map saving and loading.

For a phone's frame budget, WebVIO adds options. Each one is off by default, so the default behavior stays
ORB-SLAM3's:

- a hybrid front end: ORB features on some frames, pyramidal KLT optical flow on the frames in between;
- optical flow split over four threads;
- a pose solver and a local bundle-adjustment solver that give the same results as g2o without building its graph;
- gyroscope-aided recovery after tracking loss (from the browser's DeviceMotion events);
- an AR mode that keeps the map while a virtual object is placed.

**Try it:** <https://itsaeox.github.io/CustomSLAM/>. Open the AR page (`ar.html`) on an Android phone in Chrome and
allow camera and motion access. WebVIO has been evaluated on a Google Pixel 9 in Chrome; other phones and browsers are
untested. iPhones are untested and may not work: Safari's limits on memory and threads apply.

## Status

This is research code. The evaluated build is the git tag `paper-batch-1103`. A paper describing WebVIO and its
evaluation (EuRoC, TUM-VI, a synthetic phone-model set, phone recordings, an AR leave-and-return test, 556 runs in
Chrome on a Pixel 9, and a user study) is in preparation; citation details will be added here.

## Repository layout

| Folder | What it holds |
|---|---|
| `slam/orbslam3/` | ORB-SLAM3 v1.0, vendored with its third-party libraries (DBoW2, g2o, Sophus); changes listed in `VENDORED.md` |
| `slam/port/` | WebVIO's code on top of it: the web bindings (`web/bindings.cc`), the added solvers and options, tools, and tests |
| `slam/CMakeLists.txt` | one source tree, two builds: native (reference) and WebAssembly (browser module and Node.js runner) |
| `web/` | the pages: `ar.html` (AR), `viewer.html` (dataset player), `record.html` (phone recorder), `calib.html`, `study/` (user study), and `serve.py`, the local development server |
| `docs/` | the published GitHub Pages site, generated by `scripts/build_pages.sh` (do not edit by hand) |
| `baselines/` | dataset runners: `orbslam3/orbslam3_run.cc` (native and WebAssembly) and drivers for the compared systems (AlvaAR, OpenVINS, EqVIO, MSCEqF) |
| `eval/` | trajectory evaluation (ATE, coverage, maps, AR return scoring) |
| `synth/` | generator of the synthetic phone-model sequences (rendered rooms, phone camera and IMU model) |
| `scripts/` | environment setup, builds, and the scripts of every experiment (`scripts/experiments/<date>/`) |

`webar-vio/` and the scripts and pages at the repository root (`index.html`, `kitti.js`, `tumvi.js`, `vio_wasm*`, the
`eval_*` and `summarize_*` scripts) belong to an earlier filter-based VIO prototype. WebVIO does not use them.

## Building

The builds run on Ubuntu 22.04, natively or under WSL2. Paths below are the defaults of `scripts/setup_env.sh`.

### 1. Toolchain and libraries

```bash
bash scripts/setup_env.sh
```

This installs the apt packages and builds or installs the following, at pinned versions:

- Pangolin v0.8 and ORB-SLAM3 v1.0 (only for the upstream reference runs);
- a Python environment with evo, numpy, matplotlib, scipy, pandas and pyyaml (`/opt/slam/venv`);
- Emscripten 3.1.64 (`/opt/slam/emsdk`);
- OpenCV 4.10.0, native and for WebAssembly, with and without threads (`/opt/slam/opencv-4.10.0-*`);
- Boost headers.

Steps can be run one at a time, for example `bash scripts/setup_env.sh emsdk opencv_wasm_mt`. ORB-SLAM3 needs a lot
of memory to compile, so lower `JOBS` (default 6) on machines with less than 16 GB.

### 2. Native build (reference runner and tools)

```bash
cmake -S slam -B build/slam-native -DOpenCV_DIR=/opt/slam/opencv-4.10.0-native/lib/cmake/opencv4
cmake --build build/slam-native -j 6
```

This builds `orbslam3_run`, which runs a dataset sequence and writes the trajectories (run it without arguments for
its usage), and
`vocab_convert`. WebVIO loads the vocabulary in a binary format. Convert ORB-SLAM3's vocabulary
(`Vocabulary/ORBvoc.txt` in the ORB-SLAM3 repository, unpacked) once:

```bash
build/slam-native/vocab_convert ORBvoc.txt vocab/ORBvoc.bin
```

### 3. WebAssembly build (browser module and Node.js runner)

```bash
source /opt/slam/emsdk/emsdk_env.sh
emcmake cmake -S slam -B build/slam-wasm -DBUILD_WASM=ON -DOpenCV_DIR=/opt/slam/opencv-4.10.0-wasm-mt/lib/cmake/opencv4
cmake --build build/slam-wasm -j 6 --target orbslam3_web_js orbslam3_run
mkdir -p web/build
cp build/slam-wasm/orbslam3.js build/slam-wasm/orbslam3.wasm build/slam-wasm/orbslam3.worker.mjs web/build/
```

`orbslam3.js` and `orbslam3.wasm` are the browser module that the pages load. `orbslam3_run.js` is the same code as a
Node.js program, for running datasets on a PC.

## Running the pages locally

The pages need the COOP/COEP headers that browsers require for WebAssembly threads; `web/serve.py` sends them. Point
`--root` at a folder that holds `vocab/ORBvoc.bin` (and, optionally, `datasets/` and `results/`):

```bash
python3 web/serve.py --root /path/to/research --port 8000
```

Then open <http://localhost:8000/web/ar.html> (AR) or <http://localhost:8000/web/viewer.html> (dataset player). A phone
on the same network needs HTTPS: start the server with `--host 0.0.0.0 --cert cert.pem --key key.pem`. To build
the GitHub Pages site into `docs/`, run `bash scripts/build_pages.sh path/to/ORBvoc.bin`; the script also copies
optional modules and models (EqVIO, XFeat) that it expects in `web/build/` and `web/models/`.
